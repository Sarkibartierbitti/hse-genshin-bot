# Высшая школа геншина — техническая спецификация MVP

Статус: согласованные требования, 23 октября 2026. Новый Telegram-бот, интерфейс полностью в переписке, русский язык.

## Пользователи и доступ

- Две роли: участник и организатор. Все организаторы могут создавать и редактировать любые мероприятия, посты и задания.
- Первые организаторы задаются Telegram ID при развёртывании. Далее организатор может выдать/снять роль у известного боту пользователя.
- Назначения хранятся по постоянному Telegram ID; поиск по @нику работает среди пользователей, запустивших бота.
- Личные сообщения доступны после `/start`. Подписка одна — на все публичные события, с кнопками включения и отключения.
- Внутренние карточки и операции проверяют роль на сервере, включая переходы по старым кнопкам.

## Карточки и формы

**Мероприятие:** название, дата/время, публичное или внутреннее, статус «идея / в разработке / готов / провели / отменено», несколько ответственных, локация. Для идеи дата и локация необязательны. Дополнительно: ссылка на основной пост и дата/время окончания регистрации.

**Значимый пост:** название, планируемая дата публикации, статус, ответственные, ссылка на опубликованный пост, задания. Публикация содержимого поста в канал не входит в MVP.

**Задание / подзадача:** текст, несколько исполнителей, статус «открыто / выполнено», необязательный собственный дедлайн. Без дедлайна используется дата мероприятия; у самостоятельного поста — планируемая дата публикации. Подзадачи образуют один уровень вложенности.

Формы пошаговые, с кнопками, сохранением прогресса в базе и отменой. Кнопка публикации карточки в расписании отделена от готовности. Участникам видны только явно опубликованные публичные мероприятия. Неопубликованные идеи и внутренние события видят только организаторы. При необходимости дату можно изменить, мероприятие отменить, а задачу закрыть.

## Меню

- Участник: расписание по месяцам, подписка, предложить идею.
- Организатор: дополнительно внутреннее расписание, мои задания, создание мероприятий и постов, управление ответственными и ролями.
- Расписание — список по датам с переключением месяцев и переходом в карточки.
- Пост для привязки алерта можно переслать из канала или прислать ссылку `https://t.me/...`; регистрация остаётся внешней.

## Напоминания и предложка

| Основание | Интервалы | Получатели |
| --- | --- | --- |
| Начало мероприятия / планируемая публикация поста | 168, 72, 24 часа | Ответственные в личку и одновременно в тему чата оргов |
| Дедлайн задания / подзадачи | 168, 72, 24 часа | Исполнители в личку и одновременно в тему чата оргов |
| Окончание регистрации | 72, 24 часа | Подписавшиеся в личку и группы, куда добавлен бот; исключая чат оргов |

- Без тихих часов. Храним время в UTC, ввод и показ по Москве. Момент отправки равен дедлайну минус интервал; обычная погрешность — один запуск планировщика и доставка Telegram.
- Публичное напоминание содержит ссылку на основной пост. Без ссылки или даты окончания регистрации рассылка регистрации не создаётся.
- Перенос дат пересчитывает ожидающие отправки; завершение, отмена, снятие подписки и удаление бота из группы выключают ненужные отправки.
- Старые интервалы для только что созданной карточки не отправляются задним числом. Просроченные задания видны в списке, но ежедневных повторных пингов в MVP нет.
- Предложение из лички сохраняется и передаётся в отдельную тему беседы оргов, с указанием автора. Можно отправить текст или медиа. Ответ из чата оргов пользователю не входит в MVP.

## Развёртывание и хранение

- TypeScript, Cloudflare Worker (Telegram webhook), D1 (SQLite), Cron каждую минуту и управляемая очередь Cloudflare Queues для рассылок. Без ВМ, AI API, отдельного сайта и постоянного polling-процесса.
- Основные таблицы: пользователи, карточки, ответственные, задания, исполнители, формы, группы, настройки, предложения, журнал обновлений Telegram и очередь уведомлений.
- Webhook проверяет `X-Telegram-Bot-Api-Secret-Token`. Повторные входящие обновления учитываются по `update_id`.
- Уведомления хранятся в базе: уникальный ключ, запланированное время, получатель, попытки, блокировка обработки, результат отправки. Короткие пакеты отправок учитывают ограничения бесплатного тарифа и Telegram `retry_after`.
- Cron передаёт наступившие уведомления в Queues; отдельные запуски Worker отправляют их пакетами по 10. Это снимает ограничение «один пакет получателей в минуту». D1 остаётся источником истины при повторах сообщений очереди.
- Обычные ответы интерфейса сохраняются в очереди одновременно с завершением входящего обновления, затем отправляются сразу. Сбой Telegram не применяет введённый текст к следующему шагу формы повторно; недоставленный ответ повторяется из базы с проверкой роли.
- Перед отправкой повторно проверяются роль, видимость, подписка и актуальная версия карточки. Секреты и содержимое предложений не пишутся в технические логи.
- Сбой между успешной отправкой в Telegram и записью результата теоретически может дать дубль: Bot API не предоставляет ключ идемпотентности для `sendMessage`. Абсолютная доставка ровно один раз не обещается.

## Что нужно для запуска

1. Бесплатный аккаунт Cloudflare; вход через Wrangler OAuth. Домен и ВМ не нужны.
2. Новый бот через @BotFather и его токен, введённый локально в защищённый файл/Cloudflare Secrets, а не в чат и не в Git.
3. Telegram ID первых организаторов; бот показывает собственный ID командой `/id`.
4. Добавить бота в беседу оргов. Организатор выполняет `/orgchat` в теме напоминаний, `/suggestionschat` в теме предложений. В публичных группах бот регистрирует своё добавление автоматически.

## Проверка готовности

- Участник не может прочитать внутреннее событие по кнопке или вызвать орг-команду.
- Орг создаёт и изменяет мероприятие/пост, назначает нескольких ответственных, создаёт и закрывает подзадачи с дедлайном и без.
- Повторный webhook не создаёт вторую карточку/предложение; перезапуск не теряет форму или ожидающие уведомления.
- Календарь, подписки, приватность, перенос даты, отмена, 168/72/24 часа и 429 Telegram проверяются автоматическими тестами.
- Проходят TypeScript, тесты, применение локальных миграций D1 и сборка Worker. Живое подключение Telegram проверяется после настройки аккаунта и токена.

Источники: [D1](https://developers.cloudflare.com/d1/get-started/), [Cron](https://developers.cloudflare.com/workers/configuration/cron-triggers/), [Telegram Bot API](https://core.telegram.org/bots/api).
